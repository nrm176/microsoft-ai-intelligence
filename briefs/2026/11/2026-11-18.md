## 2〜5. 重要更新、社内DXへの意味、ユースケース、統合パターン、一次情報

### 1. Foundry IQ — Knowledge graphs、SharePoint ACL、Microsoft Retriever 1、Serverless

**何が変わったか【一次情報で確認】** Knowledge graphsとMicrosoft Retriever 1がPublic Preview。SharePoint権限を維持するknowledge sourceはGA。Serverlessは2026年12月GA予定。

**なぜ重要か【分析】** RAGを文書単位の検索から出典付きの関係検索へ拡張できる。

**ユースケース【提案】** 契約書・案件・取引先間の関係追跡。SharePoint権限に応じた社内検索。

**技術的示唆【分析・提案】** Ontologyまたは既存グラフを使いGQL/自然言語で照会。Retriever 1は既存indexで利用でき再index不要。Serverlessの本番SLAは12月GA予定で現時点のGAと混同しない。

**一次情報** [Microsoft公式](https://techcommunity.microsoft.com/blog/azure-ai-foundry-blog/foundry-iq-introducing-knowledge-graphs-engineered-for-agents/4572683) / [Microsoft公式](https://techcommunity.microsoft.com/blog/azure-ai-foundry-blog/microsoft-retriever-1-brings-sub-second-agentic-retrieval-to-foundry-iq/4573431)

### 2. Work IQ — Listen、Business Applications、Memory、Teams real-time transcripts

**何が変わったか【一次情報で確認】** イベント駆動のListen、Dynamics 365/Power PlatformとMicrosoft 365を横断する業務コンテキスト、会議中の文字起こし参照、セッションをまたぐMemoryを発表。ERP連携はPreview。

**なぜ重要か【分析】** CRM/ERPの構造化データとメール・会議の非構造化情報を同一エージェントに接続する方向性。

**ユースケース【提案】** 商談・顧客会議と案件DBを照合した営業支援。イベントを起点にした承認・追跡。

**技術的示唆【分析・提案】** 権限と監査境界を検証。Listenのイベント再配信時の冪等性を設計。既報のSharePoint 60超操作は新規発表として重複計上しない。

**一次情報** [Microsoft公式](https://techcommunity.microsoft.com/blog/microsoft_365blog/whats-new-in-work-iq-at-ignite-2026-agents-that-get-work-done/4572219)

### 3. Microsoft 365 Copilot Cowork — Autoのモデル選択・subagents、プロアクティブ提案

**何が変わったか【一次情報で確認】** Microsoft-Decision-1.1を用いたAutoが工程別にモデル・推論量を選び、subagentsを並行実行。Work IQによる作業提案もFrontierで展開。Brand Kitや一部プラグインはGA。

**なぜ重要か【分析】** 複雑な業務を単一モデルに固定せず、成果物ベースで委譲する構成へ進む。

**ユースケース【提案】** 営業レビュー資料とフォローアップ計画の同時作成。経営会議向け複数資料の差分分析。

**技術的示唆【分析・提案】** FrontierとGAを区別して導入。モデル選択と処理費用の実測を行う。

**一次情報** [Microsoft公式](https://techcommunity.microsoft.com/blog/microsoft-copilot-blog/whats-new-in-copilot-cowork-at-ignite-2026/4572242)

### 4. Azure AI Gateway — 独立したマネージドAI GatewayのGA

**何が変わったか【一次情報で確認】** 従来Azure API ManagementのAI Gateway tierとしてPreviewだった機能が、モデル・MCPツールへのアクセス、ポリシー、費用、利用状況を統合する独立サービスとしてGA。

**なぜ重要か【分析】** 複数プロバイダーのモデル・ツール接続に統一制御点を置ける。

**ユースケース【提案】** 社内アプリ群のモデルAPI利用量とアクセス統制。

**技術的示唆【分析・提案】** 既存Functions直結とGateway経由の費用・遅延を比較。Entra認証、認可、MCP制限を確認。

**一次情報** [Microsoft公式](https://techcommunity.microsoft.com/blog/IntegrationsonAzureBlog/azure-ai-gateway-is-now-generally-available-ship-faster-stay-in-control/4572644)

### 5. Microsoft Agent 365 — Business Analyticsとライセンス範囲変更

**何が変わったか【一次情報で確認】** Agent 365 Business AnalyticsはFrontier Preview。対象Microsoft 365契約に含まれる基本エージェント可視化のライセンス変更がGA。高度な非Microsoftエージェント管理・統制はAgent 365またはME7が必要。

**なぜ重要か【分析】** 全エージェントの費用対効果と管理責任を一元化しやすいが、契約別機能差の確認が必要。

**ユースケース【提案】** エージェント別の所有者、費用、利用率を棚卸し。

**技術的示唆【分析・提案】** 対象M365契約とpremium境界を確認。エージェントの登録・所有者・ライフサイクルを定義。

**一次情報** [Microsoft公式](https://techcommunity.microsoft.com/blog/agent-365-blog/whats-new-in-microsoft-agent-365-ignite-2026/4571753)

### 6. Azure Functions / Durable Task Scheduler — Durable Agent Framework GA、LangGraph連携Preview、private endpoint/CMK GA

**何が変わったか【一次情報で確認】** Microsoft Agent Framework向けDurable ExtensionがGA。LangGraphのDurable Task Scheduler連携はPreview。DTSのprivate endpointsとcustomer-managed keysがGA。

**なぜ重要か【分析】** Functions中心の社内エージェントで長時間実行と復旧、ネットワーク・暗号鍵統制を実現しやすい。

**ユースケース【提案】** 長時間の帳票処理・照合・承認フロー。

**技術的示唆【分析・提案】** 冪等なactivity、チェックポイント、再実行設計。Flex Consumptionとの適合性・料金を検証。

**一次情報** [Microsoft公式](https://techcommunity.microsoft.com/blog/appsonazureblog/whats-new-in-azure-functions-durable-task-scheduler-durable-agents-disaster-reco/4573351)

### 7. Microsoft Foundry / Azure Monitor — 外部エージェントの監視・評価GA、cross-agent debugging Preview

**何が変わったか【一次情報で確認】** 外部エージェントのobservabilityとevaluationがGA。cross-agent debuggingとAzure Monitor traces/Trace AnalyticsはPublic Preview。OpenTelemetryで実行・費用・品質を関連付ける。

**なぜ重要か【分析】** Foundry以外のフレームワークを含むエージェント運用の可観測性が改善。

**ユースケース【提案】** Python FastAPIエージェントのトレース・品質評価・費用監視。

**技術的示唆【分析・提案】** Application Insightsへ互換トレースを送信しFoundryへ登録。プロンプト・応答ログの機密情報保護とRBACを確認。

**一次情報** [Microsoft公式](https://techcommunity.microsoft.com/blog/azureobservabilityblog/agent-observability-in-azure-monitor-at-ignite-2026/4573966)
