# Microsoft AI Brief — 2026-11-06

**要点：** Work IQのSharePoint操作がPublic Previewとなり、Foundry向けazd拡張がGAに。Foundry LocalはNVIDIA GPU上のローカルcoding agent構成を公開しました。11月5日付のFoundry月次まとめは既報の総括が中心のため独立項目には含めません。

## 1. SharePoint ToolsのPublic Preview（2026-11-03）

**製品・提供状態：** Work IQ / SharePoint Tools / public_preview

### 1) 何が変わったか【一次情報に基づく事実】
Work IQ MCPに60種類以上のSharePoint操作が追加された。リスト・ライブラリの検索、作成、更新、承認、共有、バージョン管理などに対応。WorkIQ.ReadとWorkIQ.Actの権限スコープが導入された。

### 2) なぜ重要か【分析】
既存のMicrosoft 365権限を継承しながら、エージェントからSharePoint上の業務操作を行える。読み取りと変更権限の分離が重要。

### 3) 具体的なユースケース【提案】
- 社内規程ライブラリから根拠付き回答を生成
- 案件管理用SharePoint Listの項目作成・更新と承認処理

### 4) 技術的な示唆・統合パターン【事実と設計提案】
- MCPエンドポイントはhttps://workiq.svc.cloud.microsoft/mcp
- WorkIQAgent.Askのみでは/sharepointパスは見えない
- パスとスキーマは実行時に発見し固定実装を避ける
- Copilot Creditsの従量課金でMicrosoft 365 Copilotライセンスとは独立

### 5) 重要な一次情報
- [Introducing SharePoint tools in Work IQ](https://techcommunity.microsoft.com/blog/spblog/introducing-sharepoint-tools-in-work-iq/4569917)
- [SharePoint Tools for Work IQ](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/sharepoint-iq)

## 2. microsoft.foundry拡張1.0がGA（2026-11-05）

**製品・提供状態：** Microsoft Foundry / Azure Developer CLI / ga

### 1) 何が変わったか【一次情報に基づく事実】
Azure Developer CLIのmicrosoft.foundry拡張バンドルがv1.0で一般提供。Hosted Agentsの初期化、ローカル実行、診断、監視、デプロイをazdから行える。

### 2) なぜ重要か【分析】
エージェント設定とデプロイ構成をazure.yamlでコードと一緒に管理し、環境差分やCI/CDを標準化できる。

### 3) 具体的なユースケース【提案】
- Python Agent Frameworkで作る社内エージェントのDev/UAT/Prod展開
- 評価データと採点基準をGitHub Actionsで継続実行

### 4) 技術的な示唆・統合パターン【事実と設計提案】
- azd 1.37.0以降が必要
- azd ext install microsoft.foundry
- azd ai agent run / azd deploy / azd ai agent monitor --follow
- 必要に応じBicepまたはTerraformをejectして編集
- Azureリソースとモデル推論には別途費用が発生

### 5) 重要な一次情報
- [Microsoft Foundry extension for Azure Developer CLI is generally available](https://devblogs.microsoft.com/foundry/microsoft-foundry-azure-developer-cli-ga/)

## 3. Qwen3.8-27Bのローカルagentic coding統合（2026-11-05）

**製品・提供状態：** Foundry Local / GitHub Copilot / technical_release

### 1) 何が変わったか【一次情報に基づく事実】
Foundry Local CLI 0.13.0以降とGitHub CopilotのBYOK接続を使い、Qwen3.8-27Bをローカルで実行する手順とNVIDIA GPU最適化を公開。INT4でモデルサイズ約18GB、24GB VRAM環境で最大64Kコンテキストを案内。

### 2) なぜ重要か【分析】
ソースコードをローカルに保つ開発選択肢が増える一方、今回の最適化はNVIDIA向けでありMac対応は今後の計画。

### 3) 具体的なユースケース【提案】
- 機密性の高い社内コードのローカル補完・修正
- ローカル推論とクラウドモデルの成功率・速度・費用比較

### 4) 技術的な示唆・統合パターン【事実と設計提案】
- Foundry Local CLI 0.13.0以上、NVIDIA GPU 24GB VRAM以上が案内条件
- GitHub Copilot appのModel providersでFoundry LocalのAPIエンドポイントを登録
- Mac・AMD GPU向けの同最適化は未提供の計画段階
- 公開ベンチマークは特定環境の評価で一般化できない

### 5) 重要な一次情報
- [Bring Agentic Coding On-Device with Foundry Local](https://devblogs.microsoft.com/foundry/foundry-local-agentic-coding-qwen3-8-27b/)
