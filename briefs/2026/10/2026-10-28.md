### 1. 組織IDによるserver-to-server認証をPublic Preview提供 — GitHub Copilot SDK / GitHub Apps
**発表・基準日：** 2026-10-27 ／ **区分：** public_preview

**① 何が変わったか【一次情報】** 組織にインストールしたGitHub Appの短期installation access tokenを使い、ユーザーのサインインに依存せずCopilot SDKから推論要求できる。組織権限Copilot RequestsはRead-onlyで、利用料・モデルポリシー・予算は組織に帰属する。

**② なぜ重要か【分析】** 無人エージェントを個人アカウントから分離できるが、組織所有のGitHub Appと課金統制が必要。個人アカウントへのAppインストールは対象外。

**③ 具体的なユースケース【提案】** 組織内の定期コードレビューやCI補助エージェント／サービスIDで動く自動化の利用量をapp_client_idで追跡。

**④ 技術的な示唆【事実と設計判断を区別】**
- 組織にGitHub AppをインストールしCopilot Requests権限を設定
- installation tokenは約1時間で失効するため更新処理が必要
- GitHub Actionsの組織所有リポジトリではGITHUB_TOKENとcopilot-requests: writeの別経路を利用できる
- Copilot RequestsのRead-onlyは無料・無課金を意味しない

**① 何が変わったか【一次情報】** 2026年11月1日以降、新規・更新される対象Power Platform/Dynamics 365ライセンスにseeded AI Builder Creditsは付与されない。既存の契約期間中のクレジットは維持される。AI Builder機能自体は終了せず、必要に応じCopilot Creditsで継続利用する。

### 4. Assisted permissionsがGA — GitHub Copilot CLI / App / VS Code
**発表・基準日：** 2026-10-26 ／ **区分：** general_availability

**① 何が変わったか【一次情報】** コマンド実行、ファイルパスアクセス、URLオープンの許可要求をLLMが判定し、明らかに安全と分類された操作を自動許可するAssisted permissionsがGA。その他は利用者承認を求める。

**② なぜ重要か【分析】** 全許可より制限を保ちつつ、開発者の承認負担を減らせる可能性がある。

**③ 具体的なユースケース【提案】** VS Codeでの社内アプリ開発時に低リスクのローカル操作だけを自動許可。

**④ 技術的な示唆【事実と設計判断を区別】**
- CLIでは/permissionsからassistedを選択
- 管理者はAllow Allを禁止したままAssistedを許可、またはAssistedも禁止できる
- これはChatGPT Scheduled Taskの外部書き込み承認機構とは別機能
