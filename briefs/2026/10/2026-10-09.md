# Microsoft AI Brief — 2026年10月9日

**対象期間：10月7〜9日。** 前回10月8日のMXC、Copilot sandbox、HydraFusionは再掲しない。10月8日のCRM新発表と、前回未収録の10月7日Copilot Studio発表を中心に整理。

## 1. Dynamics 365の30種類のSkillsとTeams内CRM

**事実：** Microsoftは10月8日、Dynamics 365 Sales／Customer Service／Customer Insights向けに30種類の事前構築済みSkillsを発表。CoworkでGA、Autopilotでprivate preview、CodeではFrontier Program向けに提供。Dynamics 365 MCP serversを通じ、顧客情報の参照、リスク案件の抽出、CRM更新案の作成などを支援する。顧客アカウントとTeamsチャネルを結び、会議前の要約やケース通知を行う「Dynamics 365 CRM in Teams」はpublic preview。Work IQはCRMとMicrosoft 365の文脈を結合する。

**なぜ重要か：** CRM画面に移動するのではなく、TeamsやCopilotの仕事の流れで顧客情報を参照・操作する設計が具体化。

**ユースケース：** 商談リスクの早期発見、顧客会議前の準備、Teams内でのケース共有。

**技術的示唆（分析）：** Dataverseの独自アプリで同じSkillsが使えるとは限らないため、Dynamics 365固有機能と一般のDataverse API/MCPの適用範囲、ライセンス、承認フローを分けて検証すべき。

出典：https://www.microsoft.com/en-us/copilot/blog/2026/10/08/bringing-crm-into-the-flow-of-work-and-agents-into-business-process-for-sales-and-service-teams/

## 2. 自律型Service AgentとSales Development Agent、課金開始予定

**事実：** Service Agent in Microsoft 365の拡張は一部Frontier顧客向けprivate preview。メールで受けた問い合わせを理解し、回答案を作り、必要に応じCRMケースを作成する。Sales Development Agentはpublic previewで、見込み客の調査、メール送信、追跡、営業担当者への引き継ぎを担う。固有のExchangeアカウントを利用し、**2026年11月16日からCopilot creditsを消費する予定**。

**なぜ重要か：** 自律的な外部顧客対応は、機能だけでなく代理送信の権限、監査、コスト上限の設計が必要。

**ユースケース：** 夜間の問合せ一次対応、営業候補の調査・追客。

**技術的示唆（分析）：** Agent 365による管理、固有ID、メール送信ルール、停止条件、credits消費の監視をPoCに含める。

出典：https://www.microsoft.com/en-us/copilot/blog/2026/10/08/bringing-crm-into-the-flow-of-work-and-agents-into-business-process-for-sales-and-service-teams/

## 3. Copilot Studio Hooks（preview）：エージェントの決定論的な実行制御

**事実：** GitHub Copilot harnessを使うCopilot Studio agent向けHooksがpreview。セッション開始、プロンプト入力、ツール実行前後、エラー発生時などにworkflowを自動実行する。Pre tool useでは引数を検査・変更し、ツール呼び出しを拒否できる。**重要な制約：hook workflowが失敗・タイムアウトすると、agentがそのまま実行を続ける場合がある。** MicrosoftはHooksを重要なセキュリティルールの唯一の防御策にしないよう明記。

**なぜ重要か：** AIの判断と独立した監査・入力検査・処理をエージェントの実行ライフサイクルへ挿入できる。

**ユースケース：** Dataverse更新前の事前チェック、MCPツール呼出しの監査、結果の機密情報マスキング。

**技術的示唆（分析）：** Hooksは補助的な制御とし、最終的な認可・権限制御はAPI／Dataverse側で強制する。

## 4. Copilot StudioとFoundry IQの統合がGA

**事実：** Copilot StudioからFoundry IQのknowledge baseへ接続する統合がGA。複数のエージェントが同じKBを再利用でき、検索範囲を用途ごとに設定できる。private networkingにも対応。Microsoft Learnによると、GitHub Copilot harnessを使うagentが対象で、現時点では1 agentにつきFoundry IQ接続は1つ。

**なぜ重要か：** 社内文書の検索基盤と業務エージェントを分離し、ナレッジの検索・ランキング設定を集中管理できる。

**ユースケース：** 契約書、社内規程、設計基準を参照する複数の部門別エージェント。

**技術的示唆（分析）：** Entra認証、KB再利用、引用の精度、接続数の制約、従量課金を確認するPoCが有用。

## 5. Copilot Studioの評価拡張とReview panel GA

**事実：** Copilot Studioの評価対象がAI nodeとautomation全体へ拡張。Task Completion、Tool Accuracy、Safety、Latency、Custom Graders Libraryなどを利用できる。Review panelはGAで、公開前のブロック要因、組織ポリシー、未評価やモデル変更後の評価不整合を検出できる。Evaluation Viewer roleも追加。

**なぜ重要か：** エージェントの「自然な回答」ではなく、業務を正しく完了したかを評価・公開判定できる。

**ユースケース：** 案件登録agentのツール選択テスト、非エンジニア作成agentの公開前審査。

**技術的示唆（分析）：** 評価をリリースゲートに組み込む。Review panelは管理者による全社監査の代替ではない。
