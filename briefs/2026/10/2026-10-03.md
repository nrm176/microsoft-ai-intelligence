## 1. Work IQ が業務アプリケーションのコンテキストまで拡張

### 確認できた事実

Microsoft は 2026年9月25日、Work IQ が Dynamics 365 と Power Platform の中核業務データを Copilot とエージェントのグラウンディングに利用できるようになると発表しました。プレビューは 9月30日から開始され、10月にかけて展開されます。

対象には Dynamics 365 Sales / Customer Service、Power Apps、サードパーティの Line-of-Business アプリが含まれ、Dynamics 365 Finance and Operations についても10月後半からの展開が示されています。

さらに Work IQ MCP Server、Work IQ CLI、コーディングエージェント向けプラグインを通じて、承認されたビジネスコンテキストを開発環境へ持ち込む方向性も示されています。

### なぜ重要か

従来の Work IQ は「誰が誰と働き、どのメール・会議・文書が関係するか」という Microsoft 365 上の仕事コンテキストが中心でした。今回の拡張により、CRM/ERP/Power Platform の **業務レコード、関係性、プロセスルール** まで同じコンテキスト層に入ってきます。

### ユースケース

- 商談更新時に CRM 上の Opportunity だけでなく、未解決の問い合わせや直近メールまで含めて更新リスクを判断する。
- 営業・サービス・財務・サプライチェーンを横断したエージェントを作る。
- 開発者が Work IQ MCP を利用し、業務定義を理解したコーディングエージェントを構築する。

### 分析・示唆

**分析:** Microsoft は Work IQ を「Microsoft 365検索API」ではなく、業務アプリを横断する再利用可能なコンテキスト／アクション層へ拡張しようとしているように見えます。

社内DXの観点では、エージェントごとに Dataverse や Dynamics の意味論を個別実装するのではなく、共通のビジネスコンテキストを Work IQ 側で定義・統制する設計が今後重要になる可能性があります。

## 2. Fabric IQ が Copilot の「信頼できる数値・業務定義」の供給元へ

### 確認できた事実

Microsoft は 2026年9月28日、Fabric IQ が Microsoft Copilot Chat と Copilot Cowork で GA になったと発表しました。

Power BI のセマンティックモデル、指標、関係性、業務定義を Copilot の回答やマルチステップ作業に利用できます。Fabric / Power BI 顧客では既存のアクセス制御とガバナンスを維持したまま利用できるとされています。

また、組織間でデータとその意味的コンテキストを共有する **IQ Sharing** が preview として発表されました。

### なぜ重要か

生成AIで頻発する「同じ売上という言葉でも部署ごとに定義が違う」「AIが別の数値を回答する」という問題に対して、Power BI の既存セマンティックモデルを AI の共通意味論として再利用する戦略です。

### ユースケース

- 「最新の売上予測は？」という質問を、経営レポートと同じ Power BI セマンティックモデルに基づいて回答する。
- Cowork が Fabric IQ の数値を使い、その後の分析・資料作成・アクションまで継続する。
- グループ会社や取引先へ、元データを直接渡さず統制されたビジネスコンテキストを共有する。

### 分析・示唆

**分析:** Fabric IQ は BI 製品の追加機能というより、AIエージェントに「企業内で合意された数字と業務概念」を供給するセマンティック層として位置付けられつつあります。

これは、社内AIで独自に KPI 定義やデータ辞書を再構築するよりも、既存の Power BI semantic model を AI の semantic contract として再利用するアーキテクチャを検討する理由になります。

## 3. Microsoft Foundry Routines が GA — エージェントの定期・イベント駆動実行をマネージド化

### 確認できた事実

Microsoft は 2026年9月24日、Foundry Agent Service の **Routines** を GA としました。

Routines は以下のトリガーをサポートします。

- 指定日時
- 定期スケジュール
- 外部イベント

初期のイベント連携として GitHub Issue と Microsoft Teams チャネルメッセージが示されています。実行履歴、認証、トリガー、エージェントアクションを Foundry project 内で管理します。

Hosted Agent が自分自身を後で再実行する reminder tool も preview として提供されています。

### なぜ重要か

従来、定期エージェントを作るには scheduler、queue、webhook、認証、実行履歴、監視を個別に構築する必要がありました。Routines はこの周辺インフラを Foundry 側へ吸収します。

### ユースケース

- 毎朝の社内ニュース要約。
- GitHub Issue 作成をトリガーとした自動トリアージ。
- Teams の問い合わせを検出してナレッジ検索と回答準備を実行。
- 長時間処理を開始し、一定時間後に同じ会話コンテキストで再確認する。

### 分析・示唆

**分析:** Microsoft Foundry は「エージェントを作る場所」から「エージェントを継続運用するランタイム」へ役割を広げています。

今回構築している Microsoft AI Brief のような定期収集ワークロードは、将来的には ChatGPT Scheduled Task と Foundry Routines を比較する好例になります。

Source:
https://devblogs.microsoft.com/foundry/from-chatbots-to-automated-assistants-routines-in-microsoft-foundry-are-now-generally-available/

## 4. Hosted Agent の outbound network egress 制御が強化

### 確認できた事実

Microsoft Foundry は 2026年9月24日、Hosted Agent が接続できる外部宛先を outbound policy で定義し、Audit で通信を確認し、Enforced mode で許可・拒否を強制できる仕組みを紹介しました。

### なぜ重要か

エージェントが MCP server、API、外部Webサービスを自律的に呼び出すようになると、「どのデータへアクセスできるか」だけでなく「どこへ通信できるか」が企業向けセキュリティの重要な制御点になります。

### 分析・示唆

**分析:** Agentic AI の本番導入では、従来のアプリケーションと同様に network egress policy が標準要件になりつつあります。MCP を導入する場合も、ツール許可リストだけでなくネットワークレベルの出口制御を組み合わせる設計が望ましいと考えられます。

- Microsoft 365 admin center から複数の生成AI開発環境で作られたアプリを一元管理する。

### 分析・示唆

**分析:** Microsoft は「自然言語でアプリを作ること」自体より、**Open Build / Managed Run** に近い企業向け運用モデルを差別化要因にしようとしているように見えます。

## 6. Foundry IQ の現在地：マルチソース知識層と Serverless の課金フェーズ

### 確認できた事実

Foundry IQ は、Azure / SharePoint / OneLake / Web など複数の知識ソースをエージェントに提供する managed knowledge layer として展開されています。Foundry IQ MCP Server を通じて MCP-compatible なエージェントから利用できる構成も提供されています。

Serverless tier は idle 時に scale-to-zero する従量型モデルで、2026年9月13日から compute と storage の課金が開始されました。

Microsoft のサンプルでは Foundry IQ と Work IQ、Fabric IQ を組み合わせ、ポリシー文書、Microsoft 365 context、業務データを一つのエージェントから利用する構成が示されています。

### 分析・示唆

**分析:** Microsoft IQ の設計は、単一の巨大RAGストアを作るよりも、データの性質ごとに専門の context provider を維持し、エージェント側で組み合わせる方向です。

- Foundry IQ: 文書・企業知識・検索
- Work IQ: 人・仕事・Microsoft 365 / 業務プロセスのコンテキスト
- Fabric IQ: KPI・業務概念・構造化データの意味論
- Web IQ: 外部Web情報

この分離は、企業内の既存データ基盤を無理に一つへ統合せず、権限と意味論を保ったままエージェントへ提供する設計として注目に値します。

## 今回のアーキテクチャ上の注目点

今回の更新をまとめると、Microsoft の企業向けAgentic AIスタックは次のように整理できます。

```text
Enterprise Context
├── Work IQ     : 人・仕事・業務プロセス
├── Fabric IQ   : KPI・構造化データ・業務意味論
├── Foundry IQ  : 文書・ナレッジ・検索
└── Web IQ      : 外部Web

        ↓

Agent / Reasoning
Microsoft Foundry / Copilot / Copilot Studio

        ↓

Automation
Foundry Routines

        ↓

Application Runtime
Copilot Managed Runtime

        ↓

Governance
Entra ID / M365 Admin / Power Platform Admin / Network Policy
```

**分析:** 特に重要なのは、Microsoft がモデル性能だけでなく「企業コンテキスト → 推論 → 継続実行 → アプリ実行 → ガバナンス」を一つのスタックとして揃え始めた点です。企業のAIアーキテクチャでは、モデル選定よりもこのコンテキスト層と実行・統制層の設計が差別化要因になっていく可能性があります。
